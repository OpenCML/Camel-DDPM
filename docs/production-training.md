# 通用中英文文生图：生产目标与当前差距

用户目标是所有学习组件从零训练、尽量以 Camel 实现的生产级通用文生图。
256 张图片、约 300 万参数、64px、两个阶段各 500 步，只能证明基础流程可执行，不能作为该目标的训练配置。
重复小数据、单纯增加步数或只扩大参数量都不能替代数据覆盖与质量验收。

## 已授权资源与数据传输

用户已授权长期使用四张 GPU。2026-10-18 的资源检查：

- 使用物理 GPU 1、2、6、7：四张 RTX 3090，每张 24GiB。0、3、4、5 上有现有显存占用，不使用。
- 跨两个 NUMA 域，经 PCIe/CPU 互联，没有 NVLink。NCCL 2.20.3 和头文件已安装；这些条件不等于已验证多卡吞吐。
- 系统盘剩余约 509GB；可写目录 `/mnt/data3/zjwei` 所在盘剩余约 1.8TB，为共享可用空间，不代表全归本项目。
- 新数据放 `/mnt/data3/zjwei/Camel-DDPM-data`，先将项目新增数据预算限制在 500GB，并保留检查点和其他用户的余量。
- 用户允许本机下载后传输；本机只下载与传输。解压、筛选、图像处理、构建与训练均在服务器进行。

## 数据规模与接入

工程路线先达到 **100 万张有效、去重、审核后的图文训练图片**，验证扩展收益，再以 **1000 万张级**作为通用能力的数据规划。
这是规划目标，不是“达到这个数量就一定生产可用”的保证。需要有效中英文描述、类别/场景分布、尺寸质量、固定留出集和数据版本记录。
同一图片的多个语言或多个描述不能重复计作多张独立图片。

首个大规模来源为 [WIT 官方数据](https://github.com/google-research-datasets/wit/blob/main/DATA.md)：
官方报告 3760 万图文记录、1150 万独立图片、108 种语言；训练元数据约 25GB，拆为 10 个 gzip TSV。
先以官方 1% 样本核验解析和双语候选筛选，随后处理完整分片。元数据条数、候选 URL 数、实际下载图数、训练准入图数分别报告。
`tools/index-wit.py` 流式解析，用磁盘 SQLite 去重，仅选择中英文、足够尺寸、Commons URL 和已有描述。
它不会加载任何预训练模型，也不会把尚未核验的图片授权记成“已通过”。

每张图还必须完成下载/解码、来源和个体许可证/署名信息核对、描述质量检查、重复分组以及训练/评估集合隔离。
WIT 数据集声明不能代替个体图片来源核验。未通过这些步骤的候选记录不能传给现有训练入口。
目前服务器访问 Wikimedia API 超时，Google Storage 下载仅数十 KB/s；本机到同一 GCS 文件实测约数 MB/s。
本机中转解决传输速度，不能自动解决图片准入审核与数据质量。

实际已完成官方 1% 元数据的本机下载、源 MD5/长度校验、服务器传输和流式扫描：
370,373 条源记录，英文候选 27,152 对、中文候选 3,220 对，共 30,216 个候选独立图片 URL。
**这些记录目前下载图片数为 0、训练准入图片数为 0。** 不能将候选数量报成已扩大的训练集。
元数据 SHA-256：`945de23c2370f7233a3d167a24f87870d01d239f596b4edfbb2bed81c940dc6c`。

## 模型和 Camel 能力

候选容量以数亿参数去噪器、独立文本编码器和高保真 VAE 为方向；实际宽度、深度、batch 与上下文长度由四卡显存和吞吐实测确定。
先验证 256px，再训练/验收 512px。所有权重随机初始化，不借用预训练文本编码器、VAE、感知损失或生成模型。

正式大规模训练前的依赖按顺序完成：

1. Camel 原生多进程设备执行、NCCL 梯度 all-reduce、统一 global step、失败中止和分布式 checkpoint。
   验证四卡平均梯度与等价单卡全局 batch 的数值关系，再测试多次更新及恢复。
   启动四份互不通信的单卡训练不算多卡训练。
2. 分片数据顺序、确定性 rank 分配、跨 epoch shuffle、预取和断点数据游标；不再逐图使用大量小文件反复解析。
3. 激活重计算、微批次梯度累积、BF16 存储/适用反向算子及 FP32 主状态。
   当前只有显式授权 GEMM 采用 BF16，不能当成这些能力已经完成。
4. 大模型单步显存与吞吐测量；记录真实峰值、有效图片/秒和四卡扩展比，再估算各训练阶段的时间。
5. VAE 先通过未见图片的细节重建检查，再固定潜变量变换和版本，训练文本条件生成。
   当前 VAE 重建模糊，不能因为噪声 MSE 下降而直接升级为生产编码器。

例如 [PixArt 官方实现](https://github.com/PixArt-alpha/PixArt-alpha) 使用预训练 T5/VAE 特征；
其公布的去噪模型训练成本不能直接作为本项目“全部组件从零”的预算。
当前小模型的每步时间也不能线性外推到四卡数亿参数模型。

## 交付门槛

训练损失下降、checkpoint 可恢复、图像文件可生成，只属于正确性门槛。
正式交付还需固定的中英文未见提示词集，分别评估对象/属性/数量/空间关系、构图与细节、多样性、记忆复现风险；结果保留样图，不能只报告平均 loss。
图像自编码器必须报告留出重建指标与对应图片。
服务需支持版本化模型、种子、分辨率/步数上限、输入验证、并发限额、超时、健康检查、故障恢复和实际延迟/负载测试。

四张 3090 是已授权算力，不是“保证能达到任意生产质量”的承诺。
在代表性大模型和数据管线基准完成前，不给出未经实测的训练工期或最终质量承诺。
